## TL;DR — pt-BR IS supported, the path is real (as a proof; CPT for fluency)

`annotate.py` has a `--lang` flag (default `"en"`). **Set `--lang pt`** and the
whisper-timestamped transcription runs in Portuguese. The trainer is language-
agnostic (it learns from your stereo pt-BR audio + pt transcripts). So the pt-BR
Moshi *pipeline* is supported, not a research gamble — the gamble is how far a 7B
EN/FR base transfers; J-Moshi says budget continued-pretrain, not LoRA-only.

## Data format (hard requirement)

- **Stereo wav**: left channel = Moshi/system speech, right channel = user speech.
  This is the binding constraint — we need *two-party conversational* pt-BR audio
  separable into channels (or constructable: TTS one side, or diarize+split).
- Per-file `<name>.json` = timestamped transcript (generated by `annotate.py`).
- `<dataset>.jsonl` index: `{"path": "data_stereo/a.wav", "duration": <sec>}`.
- Reference dataset to copy the shape from: `kyutai/DailyTalkContiguous` (14 GB, HF).
- jsonl generation snippet uses `sphn.durations(paths)`.

## annotate.py (the data pipeline)

- `python annotate.py <egs.jsonl(.gz)> --lang pt [--local] [-S/--shards N --partition P]`
- Uses `whisper_timestamped` (whisper `large-v3` supported), SAMPLE_RATE 16k for ASR.
- **SLURM-native** via `submitit` (`--shards`, `--partition`) → maps directly onto
  SDumont; `--local` for a single box / Colab.
- Caps files at 4h. Writes `<name>.json` next to each wav.

## Config knobs (finetune/args.py + example/moshi_7B.yaml)

| Param | Recommended (quick) | Note |
|---|---|---|
| `moshi_paths.hf_repo_id` | `kyutai/moshiko-pytorch-bf16` (M) / `moshika` (F) | base; CC-BY-4.0 |
| `lora.enable` / `rank` / `scaling` | true / 128 / 2.0 | ≤128 rank advised; `ft_embed:false` |
| `full_finetuning` | false | true ⇒ must set save_adapters false |
| `duration_sec` | 100 | max seq seconds; lower if OOM (hurts UX) |
| `batch_size` | 16 | per GPU; lower first if OOM |
| `max_steps` | 2000 | tokens = steps×gpus×bs×dur×9×12.5 |
| `optim.lr` | 2e-6 (README curve used 4e-6) | very low LR |
| `first_codebook_weight_multiplier` | 100 | semantic codebook weighted heavily |
| `text_padding_weight` | 0.5 | text stream is mostly padding @12.5Hz |
| `gradient_checkpointing` | true | OOM mitigation |
| `save_adapters` | true | LoRA-only ckpt, works w/ moshi inference |
| `param_dtype` | bfloat16 | |
| `wandb.*` | optional | project/key/offline |

Train: `torchrun --nproc-per-node N -m train example/moshi_7B.yaml` (use torchrun
even for 1 GPU). Inference: `python -m moshi.server --lora-weight=<ckpt>/consolidated/lora.safetensors --config-path=<ckpt>/consolidated/config.json`.

## Gaps / risks (honest)

- **Stereo conversational pt-BR data is the blocker** (same as the global #1 risk).
  Most open pt-BR is mono single-speaker read speech. Need: 2-party, separable,
  spontaneous. Options in dossier 20 (data map) + in-house recording.
- 7B EN/FR → pt-BR transfer quality with small LoRA = the unknown Phase 0 resolves.
- Emotion control: Moshi has no emotion tags; emotion is implicit via audio
  context. Controllable emotion likely needs curated expressive pt-BR data +
  possibly the Step-Audio-2-style RL approach (see dossier 30 academic).
- Moshi weights CC-BY-4.0 → attribute Kyutai in any shipped product.
